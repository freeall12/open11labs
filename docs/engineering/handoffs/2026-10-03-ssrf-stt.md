## SSRF 防护（`server/lib/safe-fetch.mjs`）

用户可以填一个 URL 让服务端去取。这台机器上跑着金库，所以这条路径
必须当作"外部输入"对待：

| 防护 | 说明 |
|---|---|
| 协议白名单 | 只允许 http/https，拒 file/ftp/gopher |
| 凭证 | URL 内不得嵌 user:pass |
| 地址分类 | 拒 loopback、私网、CGNAT、link-local(含 169.254.169.254)、组播、保留段 |
| 名称 | 拒 `localhost` 及 `.local` / `.internal` 等本地后缀 |
| **DNS 重绑定** | 先解析再连；解析到私网地址一律拒绝 |
| **逐跳复验** | 每个重定向都重新校验，防止公网地址跳到私网 |
| 重定向次数 | 最多 3 跳 |
| 体积/时间 | 流式读取并封顶，不把超大响应读进内存 |
| **不带密钥** | 该抓取**永不**附加 Provider 密钥 |

12 项负例测试覆盖全部拒绝路径。**每一条负例都必须真的被拒**——
通过比失败更危险。

## 语音转文本

- 上传/录音，音频先落为资产，job 只存 `assetId`
- 该端点返回 **JSON 而非音频**，所以产物由转录文本在本地合成为 JSON 资产
- **空转录不算成功**——供应商返回空文本时报失败
- 编辑器改文字**不重新调用转录**：本版本只做上传、转录、导出

## 测试抓到的 2 个真 bug

1. **所有 IPv6 地址被误判为私网** —— 走 IPv4 分支时长度不等于 4 就返回
   "私网"，导致 `2606:4700::1111` 这类公网地址被拒。已按 IPv6 前缀正确分类。
2. **测试依赖真实 DNS** —— 改用可注入的 resolver，并新增一条
   "公网域名解析到私网地址"的重绑定测试。
