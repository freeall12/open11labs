# 检查点 2026-10-03 · YouTube 转写（开源优先路线）

## 本次变更

按用户最新要求「功能优先选择开源实现和本地化实现」，实现 YouTube URL 转写：
**yt-dlp（开源）下载音轨 → 存入本机素材库 → 用用户自己的 STT Provider 转写**。
不经过任何第三方转写服务。**未做真实下载或转写**（无密钥，且未对真实视频发起请求）。

## 为什么用 yt-dlp 而不是自研

YouTube 的提取逻辑随平台频繁变动，自研解析器必然很快失效。
yt-dlp 是长期维护的开源方案。转写部分直接复用本项目已有的
`/v1/speech-to-text` 能力，不新增外部数据流向。

## 安全边界（`server/lib/ytdlp.mjs`）

| 防护 | 说明 |
|---|---|
| 参数传递 | **数组传参，`shell: false`**，用户 URL 无法变成 shell 片段 |
| URL 白名单 | 只接受 youtube.com / youtu.be 的 https 链接 |
| 无 Cookie | 固定 `--no-cookies`，不读用户浏览器 cookie |
| 不绕过 | 不绕登录墙、年龄门槛、付费墙 |
| 限时限量 | 默认 120s、50MB 上限，超限即拒 |
| 临时目录 | `mkdtemp` 创建，`finally` 中必定清理 |
| 标题净化 | 标题只作显示名，非法字符（含 Windows 保留字符）折叠，不作路径 |

11 项测试，其中一条直接断言 **`--no-cookies` 在参数里**、
**用户 URL 是独立的 argv 元素**。

## 可用性是探测的，不是假设的

`GET /api/v1/tools` 实际运行 `yt-dlp --version` 判断。没装就**明说没装并给出安装命令**，
而不是等到提交时才失败。本机实测 `available: true`（yt-dlp 2026.07.04 + ffmpeg 已装）。

## 崩溃安全

下载完成后**先把音频落为资产**，再调用 STT。
这样"下载成功但转写前崩溃"不会丢音源，也能在失败时明确区分
「下载失败」与「转写失败」。

## 诚实声明

- 转写结果页写明：编辑文字**不会**重新调用转写
- 费用一律记「费用未知」——本应用无法获知 Provider 对音频时长的计费
- 需要用户确认内容处理权（勾选项）
