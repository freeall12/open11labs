## 关键研究：验证端点的真实存在性

规范禁止凭习惯猜端点。我用**无密钥探测**确认（401=存在，404=不存在，
零费用）：

| 端点 | 结果 | 用途 |
|---|---|---|
| `GET /v1/models` | **401 存在** | 凭证验证 + 能力发现 |
| `GET /v1/voices` | **401 存在** | 音色列表 |
| `GET /v1/voices/voice_settings` | 401 存在 | 音色默认设置 |
| `GET /v1/subscriptions` | 404 不存在 | — |
| `GET /v1/company` | 404 不存在 | — |

选择 `GET /v1/models` 作为验证端点，理由：免费、无生成、**不返回任何账户/账单/
订阅数据** —— 正好满足 `specs/BYOK.md` 对验证步骤的要求。

## 刻意的"不知道"

- **能力一律 `unverified`**。`GET /v1/models` 的响应结构没有经过认证请求验证，
  因此不把任何模型标为 `available`，上限/价格/取消能力全部留空并给出原因。
  猜测后标 `available` 是 `specs/BYOK.md` 点名要避免的失败模式。
- **费用一律 `unknown` 且 amount 为 null**。没有任何模型核验过价格；
  `character-cost` 响应头只作计量记录，**不换算成金额**。
- **不认领 streaming / cancel / idempotency**。三者都缺文档依据。
- **同步能力不假装可查**：`getStatus`/`getArtifact` 明确返回
  `CAPABILITY_UNAVAILABLE`；`cancel` 说明供应商没有该接口，取消只停本地等待。

## 错误规范化

| 情况 | code | submissionCertainty |
|---|---|---|
| 401 | PROVIDER_AUTH_FAILED | not_submitted |
| 403 | PROVIDER_AUTH_FAILED（权限不足） | not_submitted |
| 429 | RATE_LIMITED（带 retryAfter） | not_submitted |
| 400/422 | VALIDATION_ERROR | not_submitted |
| 5xx | PROVIDER_REJECTED | **unknown** |
| 超时 | NETWORK_ERROR | **unknown** |

`retryDecision()` 统一裁决：提交状态未知、或请求可能已被接受时**禁止重试**，
避免重复计费。

## 测试抓到的真实缺陷

1. `#lastModelPayload` 用了但没声明私有字段
2. `createApi` 里用 `log(...)` 但该作用域没有 `log`（在 `createLocalServer` 参数里）→ 500
3. 临时端口（0）时 Host 白名单被固化为 `127.0.0.1:0`；且外层处理器引用了
   不在作用域的 `port()` → 500。已改为共享的可变端口状态 + `adoptActualPort()`
4. 两个测试文件用固定端口，并行时 `EADDRINUSE`；改用临时端口
5. stub 里 `seen` 定义在外层对象、方法通过 `this.seen` 访问 → 500
