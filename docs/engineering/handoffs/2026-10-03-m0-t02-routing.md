## 关键设计决定

1. **路由清单从 `routes.json` 派生**，不在代码里复制一份路径表。规范里标记
   `disposition: "excluded"` 的条目自动失去路由能力。
2. **查询态不是独立路由**。`/app/image-video?modality=video` 是 image-video 页的
   模式，不是第二个页面。`QUERY_STATE_OWNER` 显式记录归属。
3. **`path: null` 的 5 条路由不可路由**。规范明确禁止猜测上游 URL，因此它们
   落到 404 并在页面上说明「待补采」。
4. **排除路由重定向到本地说明页**，用 `replace` 避免留下历史记录；不渲染任何账户 UI。
5. **404 与「已裁剪」是两个不同页面**。前者是未知路径，后者是已知但范围外——
   混为一谈会让「已决策」看起来像「出 bug」。

## 验证

命令与退出码（macOS / darwin-arm64 / Node v26.7.0）：

```
npx tsc -b --noEmit          # exit 0，无输出
npx vitest run               # exit 0 — 1 file passed, 51 tests passed
npx vite build               # exit 0 — built in 918ms
```

测试覆盖的断言：

- 33 条 in-scope 路由各自渲染独立组件，且**都不渲染首页内容**
  （用 h1 断言，深链不回落到首页）
- 10 条 excluded 路径渲染本地「已裁剪」说明，且页面上**不存在**任何
  指向账户/营销的可交互控件
- 3 条本地 BYOK 页面可渲染
- 未知路径 404 明确
- 壳层不出现「个人资料 / 通知」控件

**测试发现并修掉的真实缺陷**：`ROUTABLE_ROUTES` 最初把 `modal-query` /
`mode-query` 也当成独立路由，导致 `image-mode` 等 6 条无注册组件直接抛错、
56 个用例失败。这正是「多个 URL 伪装成独立页面」的形态，已修正。
